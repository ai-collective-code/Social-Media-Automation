Content Engine · data model

From 16 JSON files to one relational schema

Every store under data/*.json, mapped onto Postgres — normalized where a relationship is real, left as JSONB where a field is a document nobody queries into. Runnable as-is against Render Postgres via db/schema.sql.

The full model

Solid lines are foreign keys; ||--|| reads as one-to-one, ||--o{ as one-to-many. PK/FK mark keys the way the SQL file does.

The one non-obvious call: polymorphic targets

image_jobs and prompt_overrides each target either a whole post (a feed image) or one scene of a reel (a video frame) — the app has always treated those as the same kind of asset. Two nullable foreign keys plus a CHECK make Postgres itself refuse a row that points at both, or neither.

What the schema fixes, not just stores

Three of these were real, already-shipped bugs under the JSON model — not hypothetical risks.

01 · already-shipped bug

Post IDs collide across brands

MON_001 is day-based, not unique. Every JSON store bolts on a requestId and hopes every lookup remembers to filter by it. bucket_posts gets a real UUID key; the collision has nowhere to happen.

02 · already-shipped bug

The scene-ID string hack

Scenes are identified today by suffixing a post id (THU_001__s2) and parsing it back apart. That already deleted the wrong scene's frame once, via a prefix match. reel_scenes is its own table with its own key.

03 · silent drift

Hand-set updated_at

Sixteen call sites set the timestamp by hand today. A BEFORE UPDATE trigger makes it correct on every write, unconditionally.

04 · deliberate non-change

CHECK, not native ENUM

Status vocabularies here have already changed shape more than once. Widening an enum is cheap in Postgres; narrowing or renaming one isn't. A CHECK is a one-line ALTER either way.

Running it on Render

  1. Render dashboard → New → PostgreSQL, in the region closest to wherever the app runs.
  2. Copy the connection string — Internal if the app also runs on Render, External for anywhere else. 
    psql "$DATABASE_URL" -f db/schema.sql
  3. Set it in web/.env.local — Render's external URLs need sslmode=require or the connection is refused. 
    DATABASE_URL=postgres://user:pass@host/dbname?sslmode=require
